# 손글씨 편집기

## 제품 범위

손글씨 편집기는 위치 기반 다이어리에 편집 가능한 필기, 사진, 장식을
추가한다. 현재 PoC에서는 범용 노트 애플리케이션으로 확장하지 않는다.

제품 진입점은 iPad/Apple Pencil과 Android 태블릿/S Pen을 대상으로 한다.
향후 휴대폰 지원을 위해 반응형 바텀시트 구현은 내부에 유지한다.

## 확정된 결정 사항

* iPad와 Android에서 같은 문서를 이어서 편집할 수 있어야 한다.
* 다이어리 하나는 여러 페이지로 구성된 손글씨 문서 하나를 소유한다.
* 페이지 논리 크기는 세로 `900 x 1200`, 가로 `1200 x 900`이다.
* 페이지 생성, 삭제, 복제, 드래그 순서 변경을 지원한다.
* 두 플랫폼은 공통 툴바 경험을 제공한다.
* 스타일러스는 필기하고, 한 손가락은 이동하며, 두 손가락은 화면을 확대·축소하고 회전한다.
* 스타일러스가 없으면 툴바에서 한 손가락 입력을 필기와 이동 모드 사이에서 전환한다.
* 변경은 입력이 멈춘 뒤 1초 후 자동 저장하고 편집기를 벗어날 때 즉시 반영한다.
* 다이어리 하나는 최대 10페이지, 1,000획, 필기점 250,000개,
  편집 가능한 미디어 레이어 150개, 관리 원본 이미지 합계 250MB로 제한한다.
* 첫 릴리스는 데이터를 로컬에 저장하고 앱 재실행 후 복원한다.
* 다시 편집할 수 있는 원본 데이터와 PNG 미리보기를 제공하며 PDF 내보내기는 연기한다.

## 반응형 편집기 레이아웃

모든 기기에서 캔버스를 가장 중요한 작업 영역으로 사용한다. 실행 취소,
현재 필기 도구, 지우개, 도구 확장은 작은 플로팅 툴바에 유지한다. 페이지
관리, 브러시 세부 설정, 배경, 삽입, 레이어 제어는 필요할 때만 열어 필기
영역을 침범하지 않게 한다.

태블릿에서는 툴바를 페이지 위에 띄우고 보조 설정을 오른쪽 패널로 연다.
휴대폰에서는 페이지를 세로 가용 너비에 맞추고, 툴바를 하단 safe area
근처에 배치하며, 보조 설정은 스크롤 가능한 바텀시트로 표시한다. 대부분의
휴대폰에는 스타일러스가 없으므로 손가락 필기를 기본값으로 사용하고,
페이지 이동이나 확대가 필요할 때 이동 도구로 전환한다.

## 플랫폼 구조

* iOS 필기 입력 및 렌더링: PencilKit
* Android 필기 입력 및 렌더링: Jetpack Ink View API
* 공통 React Native 계층: 문서 스키마, 툴바, 페이지·레이어 연산,
  history, 저장 조정, 크로스 플랫폼 렌더링 계약

공통 획 모델을 원본 데이터로 사용한다. 네이티브 payload는 선택적 캐시이며,
다른 플랫폼에서 편집하면 무효화하고 다시 생성한다.

`InkInputAdapter`는 앱과 내부 `native-ink-view` 모듈 사이의 경계다.
PencilKit과 Jetpack Ink는 같은 typed snapshot, 증분 change, capability,
ready, error 계약을 구현한다. 플랫폼 직렬화는 모듈 내부에 숨기므로 편집
화면과 저장 계층에는 플랫폼별 분기가 없다.

초기 공통 브러시는 펜과 형광펜으로 제한한다. 지우개는 양쪽 플랫폼에서
결과를 일관되게 재현할 수 있도록 획 전체를 제거한다. 호환 가능한 표현을
정의하기 전까지 플랫폼 전용 브러시 효과는 범위에서 제외한다.

## 문서 모델

```text
HandwritingDocument
  id, diaryId, schemaVersion, selectedPageId
  pages[]
    id, width, height, orientation, background
    contentRevision, thumbnailRevision, thumbnailDirty, thumbnailUri
    layers[]
      InkLayer: strokes[]
      ImageLayer: originalUri, previewUri, pixel size, display size, transform
      StickerLayer: stickerId, size, transform
```

좌표는 화면 픽셀이 아니라 페이지 논리 단위로 표현한다. 이동 가능한 모든
레이어는 translation, scale, rotation, 배열 위치 기반 z-order, 표시 여부,
잠금 상태를 가진다.

사진과 스티커의 z-order는 다른 미디어 레이어를 기준으로 관리한다. 저장된
썸네일과 네이티브 PencilKit/Jetpack Ink 편집 화면의 합성 순서를 맞추기 위해
필기는 미디어 위에 마지막으로 렌더링한다. 올가미 도구는 여러 개의 완성된
획을 선택하고 하나의 history 작업으로 이동한다. 획 묶음의 크기 조절과
회전은 굵기, tilt, azimuth의 크로스 플랫폼 변환 정책이 필요하므로 연기한다.

## 배경과 미디어

기본 배경은 무지, 줄, 격자, 도트, 크림색 종이다. 사용자가 선택한 이미지를
배경으로 사용할 수도 있다.

이미지는 사진 보관함이나 다이어리에 첨부된 사진에서 가져온다. 원본은
변경하지 않고 보존하며, EXIF 방향을 정규화한 JPEG 미리보기는 긴 변을
4096px로 제한한다. 원본 하나는 최대 40MB, 문서 내 관리 원본의 합계는
250MB로 제한한다. 가져오기에 실패하면 생성한 원본과 미리보기를 모두
롤백한다. 카메라 촬영, 크롭, 필터, 정렬 가이드는 이번 범위에서 제외한다.

리소스 증가는 획당 필기점 20,000개, 문서 전체 필기점 250,000개, 페이지당
편집 미디어 레이어 30개, 문서 전체 150개로 제한한다. 한도에 도달하면 새
콘텐츠만 차단하고 삭제와 지우기처럼 문서 크기를 줄이는 작업은 계속 허용한다.

## 저장과 history

SQLite에는 문서·페이지 metadata와 JSON 레이어 콘텐츠를 저장한다. 관리
미디어, 네이티브 Ink 캐시, PNG 썸네일은 다이어리 문서 디렉터리에 둔다.
다이어리를 삭제하면 데이터베이스 행을 cascade 삭제하고 디렉터리도 제거한다.

실행 취소와 다시 실행은 필기, 페이지 작업, 회전, 배경, 레이어 변경을
포함한다. 메모리 history에는 최근 작업 100개를 보관한다. 자동 저장은 현재
문서만 영속화하며 편집 history를 지우지 않는다. 저장과 썸네일 캡처는
직렬화하고 오래된 페이지/revision 캡처는 폐기한다. 저장 session에 generation
경계를 두어 이전 다이어리의 저장 완료가 다음 다이어리를 저장 완료로 표시하지
않게 한다.

## 내보내기

첫 단계에서는 PNG 썸네일과 앱 내 미리보기를 생성한다. 전체 해상도 PNG도
같은 합성 renderer를 사용한다. 페이지 렌더링이 안정된 후 이미지 기반 다중
페이지 PDF를 추가할 수 있으며 vector PDF는 명시적으로 범위에서 제외한다.

## 구현 순서

1. 버전이 있는 문서 모델, 데이터베이스 migration, repository
2. 다중 페이지 상태, undo/redo, 자동 저장, 페이지 제어
3. 공통 툴바와 PencilKit adapter
4. 기본 배경
5. 변형 가능한 이미지와 번들 스티커 레이어
6. revision-safe PNG 썸네일 합성
7. Android Jetpack Ink adapter와 emulator instrumentation test
8. 자동화된 적대적 검증과 크로스 플랫폼 변환 test
9. 사용자가 수행하는 iPad·Galaxy Tab 실기기 승인(인계 대기)

필수 실기기 시나리오와 성능 기록 양식은 `HANDWRITING_DEVICE_QA.md`를 따른다.

Android Gradle Plugin 8 계열은 JDK 17 이상이 필요하고, 이 프로젝트의 Gradle
8.14.3은 실행 JVM으로 JDK 24까지 지원한다. 현재 자동 검증 기준은 JDK 21이다.
저장소는 개인 Java version manager 설정을 강제하지 않으므로 각 개발자가 빌드
셸과 IDE의 Gradle JDK를 지원 범위에 맞춘다. 이는 Android source compatibility나
앱의 runtime API level을 변경하지 않는다.
